# Forms step 3h1, the means test calculation: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One calculator works out every line of Form 122A-2 from a record of its inputs and the official tables in force on the fill date; the in-app result has four outcomes in the owner's words; an above-median filer's 122A-1 and 122A-2 refuse (the hold), and Mark as Filed can't get around it; forms filed before 3h keep what they stored, with a notice; today's wrong limit, 2024 figures and caps go (DIG-146).

**Architecture:**

- **Two dated table sets** in `apps/districts`: `MeansStandards` (one row per U.S. Trustee period, child rows `MeansFigure` and `MeansArea`) and `Section104Amounts`, loaded by data migrations and read through `apps/districts/means_standards.py`, which raises `NoMeansTestTable` (a `NoTableInForce` with its own sentence).
- **A pure calculator**, `apps/eligibility/means_lines.py` (standard library only): `MeansInputs` and `MeansTables` in, `work_out()` returns `MeansLines` (every line a figure, `MISSING` or `SKIPPED`, the row lists and the outcome); `compare()` is the one comparison. **A session reader**, `apps/eligibility/means_inputs.py`: `read_inputs(session)` and `read_tables(on)`. In 3h1 every answer the 3h2 page will ask is `None`, so an above-median result is always "can't be worked out yet".
- **`MeansTest`** stores an encrypted `outcome`; `calculate()` keeps the median comparison first and runs the calculator only above the median, turning a missing 122A-2 table into `cannot_work_out` with `tables_gap`. The table's plaintext columns are encrypted by add/copy/swap migrations.
- **Forms:** 122A-2's `requires()` refuses (a missing table, then the hold); 122A-1's `requires()` runs 122A-2's `build_parts` and `check()` above the median; Mark as Filed on an unfiled 122A-1 or 122A-2 takes the unfiled-download path first; a migration flags the pair's rows filed before 3h (O11), and the list reply carries a live boolean for H52.
- **Frontend:** the browser composes the outcome's words from `copy.ts` (`utils/meansOutcome.ts`) for the sidebar and the dashboard; the dashboard names each table set, shows O5's notice, splits the pair's refusals into a `role="status"` block, shows a refused Mark as Filed, and gives cards O11's and H52's notices.

**Tech Stack:** Django 5.0, DRF, `encrypted-model-fields` (Fernet), pypdf/PyMuPDF form engine, pytest-django (sqlite; Postgres for the `postgres` marker), React 19 + Vite + vitest + MSW, Playwright. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-13-forms-step3h-design.md` (approved by the owner on 2026-11-14), §7 (cited `§7.x`), with §6's 3h1 rule, §10's line rules, §11's copy rules, §15's calls (cited `Hn`) and Appendix A. Where this plan and the spec disagree, the spec wins, except at "Rulings". The code facts behind this plan are in `/Users/controlroom/.claude/jobs/bb720722/tmp/3h1-plan/survey/` (six reports and a critic, read 2026-11-14 on this branch's tree, develop 30797cc); the spec's working papers, with the U.S. Trustee figures as read in the spec's survey, are archived at `/Volumes/Containers/DigniFi/.claude/archive/3h-design/` (`survey/tables.md`).

## Global Constraints

- **Nothing is derived for a line the form asks the filer.** Every `MeansInputs` field the 3h2 page will ask (line 3, the vehicles claimed and Vehicle 1/2, each secured debt's payments left, change, 60-month total, taxes or insurance, line 34's question and cure, lines 15–31, line 36, line 43) is `None` from `read_inputs` in 3h1. No field is filled from a Schedule I or J figure (O1, H18).
- **Lines 6–15 take the standards whole.** No `min(actual, standard)`, no cap at actual spending (H10). The only netting is 9c = 9a − 9b, 13c = 13a − 13b and 13f = 13d − 13e, each floored at 0.00.
- **No catch-alls (H9).** No `except Exception`, no fallback to 0 or to a family size of 1, no `or Decimal("0")` in new code. A missing input makes its line `MISSING`; a table key that should exist and doesn't raises `MeansTableKeyMissing` (a `LookupError`) whose message names the table part ("housing", "area", "operating", "multiplier") and never the county, the district or any filer value (DIG-105: a 500's message reaches Sentry).
- **Rounding (H3).** Every money line is a `Decimal` quantized to `Decimal("0.01")` with `ROUND_HALF_EVEN`; a ÷ 60 row (9b, 13b, 13e, 33d, 34) rounds per row and its total adds the rounded rows; every later line computes from the rounded figures.
- **The comparison.** The thresholds come from the § 104 row in force, never from code. Line 43 is never an input of the comparison or of the outcome (§1).
- **Words.**

## Review Focus

Five conditions a filer will meet that §7 doesn't spell out, most likely first. Each has its test in the owning task.

1. **A session with no debtor details, no county or no household age yet** (an unfinished intake, or a test fixture). The sidebar's call must give "can't be worked out yet", never a 500 or a 400. 3. **Mark as Filed pressed again on a 122A-1 already filed** (a double click, or a second tab). It stays filed with the document it was filed with, and is not worked out again, even above the median. Test: Task 7, `test_marking_an_already_filed_122a1_filed_again_keeps_what_it_was_filed_with`.
4. **A below-median filer on a day with no U.S. Trustee set in force** (2026-07-14). They are never refused, and no ERROR line names the 122A-2 tables. Test: Task 5, `test_a_below_median_filer_never_reads_the_122a2_tables`.
5. **A means test reply with a null outcome** (a row saved before 3h1, or a stale context copy). The sidebar and the dashboard show no outcome words and no closing sentence, never the old "may need further review". Tests: Task 8, `shows no outcome words and no closing sentence for a null outcome` (sidebar) and `shows no result for a null outcome, and still shows the pair notice` (dashboard).

## Rulings

These settle what the spec leaves open or the code contradicts, and name what each costs if wrong. `rulings` in a task means this section.

- **R1. District keys are lower case.** The spec writes the district code `ILND`; the code stores `District.code = "ilnd"` (`ilnd_2025_data.json:6`) and the median lookup passes it as is. The multiplier's child row is keyed `"ilnd"`, and `read_inputs` lower-cases `session.district.code`. The migration notes the U.S. Trustee's spelling `"ILN"` beside it. Cost if wrong: one `.lower()`.
- **R2. The records' shapes** are fixed in Task 2's Interfaces (field names, the 80 line keys, the six row keys), because 3h2 wires answers into `MeansInputs` and 3h3 binds `MeansLines`. A line value is a `Decimal` (money), an `int` (a count), a `str` (a tick or a name), or one of the sentinels `MISSING` and `SKIPPED`. Cost if wrong: renames in 3h2 or 3h3.
- **R3. Missing, not raised.** A session with no `DebtorInfo` (the filer's age is `None`), no `Household.county`, no `ExpenseInfo` or no `ClaimAnswers` reads as missing inputs; only a key the table should hold and doesn't raises (`MeansTableKeyMissing`). The household list and income by source still raise their own `IncomeStepGap`/`IncomeNotSplit` from `household_members`/`household_cmi`, which `calculate()` already checks first. Cost if wrong: a 500 in the sidebar.
- **R4. A lapsed 122A-2 table logs once per lookup.** `calculate()`, 122A-1's nested `build_parts('form_122a2')` and 122A-2's own `requires()` each look the tables up, so one Generate All can log the same ERROR line three times. Tests assert that every ERROR record is exactly that line (no filer data), not how many there are. Cost if wrong: two extra log lines while a table has lapsed.
- **R5. Encryption by add/copy/swap,** as `apps/intake/migrations/0032`–`0034` do. An in-place `AlterField` of a boolean to `EncryptedBooleanField` casts to `'true'`/`'false'` on Postgres, which Django's `BooleanField.to_python` refuses, and an in-place decimal stays plaintext. - **R6.

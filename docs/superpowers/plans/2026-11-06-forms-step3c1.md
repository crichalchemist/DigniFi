# Forms step 3c1, the engine: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let one form continue several repeat groups on copies, number its pages across all of them, print a group's page totals and last-page total, and stop a number box refusing a row the form can reach, all proven on synthetic schemas with no change to any production form.

**Architecture:** `page_numbers` moves from `GroupSpec` to `FormSchema`, and numbering moves out of `_copies` to a step after every group's copies exist. A group gains an optional `totals` declaration that `_resolve_parts` writes from the values it has already resolved, so a filed document, which stores its values, never recomputes anything. `fit()` gains a `number_box` mode that `_plan` switches on only for a key some group declares in `number_boxes`.

**Tech Stack:** Django 5.0, Python 3.11, pypdf 6.13.1, PyMuPDF, pytest-django with sqlite. No migration, no frontend, no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-06-forms-step3c-design.md` §5, with §1, §2, §3 (S2, S3, S4), §4, §9.1, §9.2 and B26 (cited `§`). Where this plan and the spec disagree, the spec wins, except at "Rulings".

## Review Focus

Five conditions the spec implies and §5.5 doesn't name, most likely to bite a filer first. Each has its test in the owning task.

1. **A row with no amount on a page with other rows.** It adds nothing, and the page still prints the others' sum (Task 3, `test_a_row_with_no_amount_adds_nothing_and_the_page_still_totals`).
2. **Rows that exactly fill a copy.** Eight rows fill one copy, so there is no empty second copy, and the last-page total prints on the full one (Task 3, the "a full copy" case).
3. **A schema that declares groups out of page order.** Page positions follow the pages, not the declaration (Task 2, `test_page_numbers_follow_the_pages_not_the_order_the_schema_declares`).
4. **A form long enough for a two- or three-digit page number.** It prints whole in the 16.3 pt box (Task 4, `test_a_page_number_prints_whole_in_its_small_box`).
5. **A box with `/MaxLen` that no group numbers.** Form 101's state box still refuses three letters. 87 bound production boxes keep their limit (Task 4, `test_a_box_no_group_numbers_keeps_its_max_length`).

## Rulings

Gaps the spec leaves open, decided here. The plan's code ran in a scratch copy of the tree (see "What the dry run proved").

- **R1. The last-page box adds the group's column; it doesn't call `total_secured_claims`.** §5.3 says both that each box adds one column and that the figure is that rule's. They agree once rows are debts, and a sum can't disagree with the rows above it. Production D binds `undefined_24` to the rule (`schedule_d.json:7,15`), and a group declaring the same box is E006, so **3c5 must drop that binding** and pin the rule's figure equal to the column's sum for each persona. `schedule_d_with_totals` drops it the same way. Only D binds that rule, so whether it then stays is 3c5's call.
- **R2. A page with no row leaves its page box blank. The last-page box always prints,** "0.00" with no row, as the rule prints today (`test_continuation_copies.py:103-106` pins that, and doesn't move, since that fixture declares no totals). That holds with the group's section off too, as today's `undefined_24` has no `conditional_on`, so `_resolve_parts` takes a group's slots from `schema.fields`, not the section-filtered `groups`.
- **R3. A column the UPL guard keeps blank on any slot prints no total at all.** A figure the form leaves blank can't reach the sum beneath it, and a sum of the other rows would swear to less than the form lists. `_sheet` treats a column the same way (`all(f in printed for f in slots)`).
- **R4. D's row 12 needs more than skipping `/MaxLen`** (a correction to §5.4's B26, whose table doesn't say why it is refused). `undefined_12` has no `/MaxLen`. "2.12" at 6 pt is 11.676 pt against a field of 11.600 pt, so `fit` refuses it by 0.076 pt. Every Helvetica digit leaves at least 0.033 em clear at its right (4 and 7 in the AFM), which is 0.198 pt at 6 pt, so a number's ink stays inside the clip. A number box therefore gets that slack, **at 6 pt only and only after every normal size fails**, so no value that fits today changes size. Measured at 1440 dpi against the clip pypdf declares (right edge at `x1 − 2 × margin`): "2.14" and "2.17" clear it by 0.10 pt, "2.12" by 0.15 pt, "2.13" and "2.10" by 0.20 pt, "2.9" at 8 pt by 0.85 pt, "2.99" at 6.5 pt in `undefined_19` by 0.50 pt, and the control "2.100" at 6 pt runs 2.0 pt past it. The control's ink reaches the box's own edge, so MuPDF appears not to apply that clip (pypdf writes `re W` with no `n`), leaving only the widget's `/BBox`. Another viewer may apply it, and these margins hold either way.
- **R5. Two groups may not continue on copies of one page.** A copy's place comes from its page and number, so they would share a number. No group in §9.1 does this. New E007.
- **R6. `page_numbers` on a form with no group on copies is E007,** replacing the sheet group's own "numbers no pages" check. A leftover `page_numbers` key on a group is ignored by the loader: no production schema has one, and 3c5's generator writes the new shape. No check for it (YAGNI).
- **R7. The refusal.** `ValueTooLong` gains `ending: str = "Shorten it."`, since a filer can't shorten a row number. Group boxes read: “The entry number” is too long to fit on the court form, even in small print. This form has more entries than its boxes can hold. The same path covers the page-number boxes (“The page number”) and total boxes (“The total”), since they leak the same index labels (S4). For a total or a page number that ending is only roughly the reason, and neither is reachable: a 14-digit amount fits the total box at 7.5 pt, and a form would need 1,000 pages. The fix is `group_fix`: the `fix_for` of the group's first slot with a binding, and for a page-number box that of the first group on copies. The synthetic groups bind SOFA, so these refusals carry `page: "/sofa"`; a `household.` binding proves a `step` comes through (`test_a_groups_fix_is_where_its_rows_are_answered`). 3c5's `claims.` namespace gives `step`.
- **R8. Limits that stand after this PR,** each refused in the plain sentence: D and E/F row 100 ("2.100" is 15.01 pt at 6 pt), G row 1000 ("1000" is 13.34 pt against G's 12.32 pt field), and page 1000. G takes "999" at 7 pt, and H takes "1000" at 6 pt.
- **R9. `read_drawn`'s blank-default rule stays.** A box printing exactly its template default reads as "", so G's `fill 2.6` on a form with 5 or fewer rows reads blank, as B41 accepts.
- **R10. More pins move than §5.5 names:** see Task 2's list. All change setup, except the two E007 tests that §5.1 retires, and each keeps what it proves.
- **R11. `page_numbers` must cover every page a group continues on (E007).** A list that left one out would count that page's copies in "of N" while they print no number of their own. A form with no `page_numbers` still passes, and an entry may leave out `this`, as the moved pin at `test_checks.py:631-640` does.
- **R12. A total box must be a `Text` widget (E003).** Otherwise every filer with a row on that page gets `InvalidFieldValue`. A number or page-number box on a checkbox has the same gap today (`schema.py:630-635`). This PR leaves that as it is: see "Handed to 3c5".
- **R13. E007 doesn't check that a `column` holds amounts.** Nothing in a schema marks a binding as money yet, so a text column passes the check, and `Decimal` raises in `build_parts` for any filer with a row: a 500 logged by exception type, with no fix link. Only a schema author can cause it. A list of money bindings now would be a guess: see "Handed to 3c5".
- **R14. `_plan` reads `number_boxes` from today's schema, not from the stored part.** A schema change that drops a group's number box would refuse a filed form's stored "2.12", which §9.6's "a schema change can't alter them" forbids. No stored document can hold such a number until 3c5 declares the boxes, so changing the parts document waits for 3c5, which must settle it before the first such form is filed: see "Handed to 3c5".

```python
def _drawn(form_type, session):
    document = build_parts(form_type, session)
    pdf = PDFFormFiller().fill(form_type, document)
    return document["parts"], pdf, read_drawn(form_type, pdf, document["parts"])


def _page_numbers(drawn, this, of):
    """In printing order, each page's (template page, copy, its position, the form's count)."""
    pages = {}
    for w in drawn:
        if w.full_name in this:
            pages.setdefault((w.page, w.copy), ["", ""])[0] = w.value
        elif w.full_name in of:
            pages.setdefault((w.page, w.copy), ["", ""])[1] = w.value
    return [(*place, *numbers) for place, numbers in pages.items()]


def _printed(drawn, names):
    return {(w.page, w.copy, w.full_name): w.value for w in drawn if w.full_name in names}
```

```python
def _number_pages(schema: FormSchema, form: dict[str, str], copies: list[dict]) -> None:
    """
    With copies, every page-number box counts the copies of every group (3c spec §5.2): a page's
    position is its page number plus the copies of each page before it, and copy n of a page
    prints n places after that page. E007 keeps one group to each extra page.
    """
    if not copies:
        return
    copies_of = Counter(copy["page"] for copy in copies)
    total = page_count(schema.template_filename) + len(copies)

    def position(page: int) -> int:
        return page + sum(count for extra, count in copies_of.items() if extra < page)

    boxes_of = {boxes.page: boxes for boxes in schema.page_numbers}
    for boxes in schema.page_numbers:
        _number_page(form, boxes, position(boxes.page), total)
    for copy in copies:
        if copy["page"] in boxes_of:
            at = position(copy["page"]) + copy["number"]
            _number_page(copy["values"], boxes_of[copy["page"]], at, total)
```

```python
def _write_totals(
    group: GroupSpec, printed: list[FieldSpec], form: dict[str, str], copies: list[dict]
) -> None:
    """
    A group's total boxes (3c spec §5.3). Each page and each copy prints the sum of its own rows
    in its own box, and a page with no row leaves its box blank. The last-page box prints every
    row's sum on the last copy, or the extra page with no copy, even with no row at all.
    """
    totals = group.totals
    column = [f for f in printed if f.binding == totals.column]
    everything = []
    for values, pages in (
        (form, sorted({f.page for f in column})),
        *((copy["values"], [copy["page"]]) for copy in copies),
    ):
        for page in pages:
            amounts = [values[_key(f)] for f in column if f.page == page and _key(f) in values]
            everything += amounts
            if amounts and page in totals.page_boxes:
                values[totals.page_boxes[page]] = _added(amounts)
    if totals.last_page_box:
        last = copies[-1]["values"] if copies else form
        last[totals.last_page_box] = _added(everything)
```

```python
def _clear_of_the_clip(page, empty, widget) -> float:
    """
    Points between the drawn value's last ink and the right edge of the clip pypdf declares
    (x0 + 2 x margin + field width). Below zero, the ink runs past it.
    """
    edge = widget.rect[2] - 2 * widget.margin
    rect = pymupdf.Rect(widget.rect)
    drawn = page.get_pixmap(dpi=1440, clip=rect, colorspace=pymupdf.csGRAY)
    blank = empty.get_pixmap(dpi=1440, clip=rect, colorspace=pymupdf.csGRAY)
    rightmost = None
    for y in range(drawn.height):
        for x in range(drawn.width):
            at = y * drawn.stride + x
            if blank.samples[at] - drawn.samples[at] > 64 and (rightmost is None or x > rightmost):
                rightmost = x
    assert rightmost is not None, "the box printed nothing"
    return edge - (drawn.x + rightmost + 1) * 72 / 1440
```

**Goal:** A filer who answers Form 101 line 11's rent Yes and eviction Yes gets Form 101A in the packet. ## Review Focus

Seven conditions row 2b doesn't spell out, most likely first. Items 1, 3 and 5 are where a CLEAN task review is likeliest to be wrong, so the reviewer reads them against the code.

1. **A stale eviction Yes under a rent No.** `rents_residence` moved to No keeps `eviction_judgment == "yes"` stored (S:316). In that state:
   - no Form 101A is in the packet;
   - there is no landlord `detail`;
   - no landlord text is measured;
   - the notice is hidden;
   - the stored landlord answers sit behind the Show/Delete line.
   - Tests: Task 3 `test_a_stale_eviction_yes_under_a_rent_no_gets_no_form_101a`; Task 5 `test_a_stale_eviction_yes_under_a_rent_no_gets_no_landlord_gap_and_no_measure`; Task 6 `landlord answers kept under a rent No hide behind one line that offers Show and Delete`.
2. **A session with no `PetitionAnswers` row.** Every session saved before 4b, and every view-test fixture without `answer_petition`, has none. `applies` gives `False`, never `RelatedObjectDoesNotExist`, and `petition_step_gaps` lists nothing for 101A. Test: Task 3 `test_a_session_with_no_petition_record_gets_no_form_101a_and_no_error`.
3. **The lease pick copies a row that doesn't fit the five boxes.**
   - A pick writes all five keys from the row and overwrites what is typed (4b2-R7).
   - `street_2` is joined to the street with ", ", never dropped, never cut. A result over its cap stays and becomes the too-long `detail`; the step itself says nothing about it (the landlord is never a gate, §5.7), so the filer first reads it on Review and the dashboard. That is by design, not a miss.
   - A stored state is upper-cased and kept only when it is one of `US_STATES_AND_TERRITORIES`' codes (`petition/usStates.ts`), else null: a contract row's state is free text of two characters (`claims/AddressFields.tsx:31,70-77`, and the server takes any two letters, `backend/apps/intake/claims.py:184-185`), and the landlord's state is a select (`petition/PartyAddressFields.tsx:64-70`). Without this, `il` or `ZZ` would sit in the record, the select would show empty, the `detail` would see a state, and Form 101A would print a value the screen never showed.
   - A row ticked `outside_us` leaves state and ZIP blank. The `detail` (one fixed sentence) then stands for the whole block; it names no box. A landlord abroad can never fill the state select or the digits-only ZIP, so Form 101A stays refused for that filer: the spec's rule (S:559), put to the owner (open question 9).
   - A row with no name and no street is not offered, and no select shows when the step has no residential lease.
   - Tests: Task 6 `a pick copies every landlord box from the lease, the second street line joined`, `a lease outside the US copies no state or ZIP`, `a lease's state is copied in capitals and only when the state list has it`, `no pick is offered without a residential lease`.
4. **A landlord detail counted as a blank one, or shown twice.**

   - `FormCard` prints every detail whose `forms` names the card (`frontend/src/components/forms/FormCard.tsx:269-273`) and, below, the card's refusal (`:283-285`). After a refused Generate, Form 101A's card would show the landlord sentence twice, so a detail whose message equals the card's refusal message is skipped (4b2-R12).
   - Form 101A's boxes must be measured only while 101A is in the packet, as 103B's are (`backend/apps/forms/services/petition_fit.py:125-128`).
   - Tests: Task 5 `a too-long Form 101A answer is not counted as a blank one`, `a missing landlord is not counted as a blank answer`, `a card refused in the detail's own words shows the sentence once`; `test_form_101a_is_measured_only_while_it_is_in_the_packet`.

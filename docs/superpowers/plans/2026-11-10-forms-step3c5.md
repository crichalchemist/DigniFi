# Forms step 3c5, rows print: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Schedules D (Parts 1 and 2, with Columns A, B and C), E/F (Parts 2 and 3), G and H print every confirmed debt, notice party, contract and codebtor on its own row, on the official pages and copies of them, and H prints line 2. Nothing a filer answers changes; only what the four schedules print.

**Architecture:**

- **One read of the rows.** A new pure module, `apps/intake/claim_rows.py`, turns a session's confirmed debts, notice parties, contracts and codebtors into six ordered lists of row objects (`ClaimRows`), with each row's printed line ("2.1", "4.3") and Columns B and C worked out. `one_read_of_claims()` keeps one read per `resolve_parts` call, as `one_read_of_assets()` does.
- **A namespace.** Slots bind `claims.<list>[].<attr>`. `CLAIM_CELLS` in `fill_resolver.py` says what each attribute prints, as `ASSET_CELLS` does. `binding_fix` sends each list's refusals to `debts`, `contracts` or `codebtors`.
- **A generator.** `data/forms/field_index/tools/build_claims_schedules.py` writes the four schemas whole and their addendum rows, from the field index and hand tables of the D and E/F rows, whose names don't follow a pattern. A test holds the committed files equal to what the tool builds.
- **The engine's open ends from 3c1** close first: a parts document stores its own number boxes (R11, 3c1's R14), a number or page-number box must be a text box (R13), a group's total must add amounts (R14), and the refusals for a total or a page number get their own words (R12).

**Tech Stack:** Django 5.0, DRF, `encrypted-model-fields`, pypdf 6.13 and PyMuPDF, pytest-django with sqlite. React 19, TypeScript and vitest for one frontend fix. Playwright for the journeys. No new dependency, no migration.

**Spec:** `docs/superpowers/specs/2026-11-06-forms-step3c-design.md` §9 (cited `§9.x`), §5 for the engine, and the builder's calls B14, B25, B26, B40 and B41 (§15). Where this plan and the spec disagree, the spec wins, except at "Rulings". `PS:<line>` cites `docs/superpowers/specs/2026-10-16-forms-step3-personas.md`. The 3c1 plan's "Handed to 3c5" (`docs/superpowers/plans/2026-11-06-forms-step3c1.md:1487-1500`) lists the engine items this plan closes.

## Review Focus

Five conditions the spec implies but §9.6 doesn't name, most likely first. Each has its test in the owning task.

1. **A value too long for its row box.** A long creditor name, Sarah's 47-character joined street or a long "what it is for" must fit or be refused with the step that fixes it and the slot's own words, never a 500 and never an index label. Tests: Task 6, `test_a_creditor_name_too_long_for_its_box_is_refused_with_its_step`; Task 8, every persona's four schedules check clean.
2. **An answer the filer can no longer see.** A `collateral_who` left from before a debt moved to a vehicle row, H line 2's spouse kept under a later No, a codebtor's link to a debt now a draft or removed, a state kept on an address later ticked "outside the US". None prints. Tests: Task 2, `test_column_b_ignores_a_collateral_who_the_filer_was_not_asked`, `test_h_line_2_prints_the_spouse_only_under_both_yes`, `test_a_codebtor_link_to_a_draft_or_another_sessions_row_is_no_link`; Task 3, `test_an_address_outside_the_us_prints_no_state_or_zip`.
3. **A schema change after filing.** A filed form's stored rows, numbers, page numbers and totals redraw exactly as filed, even after the schema drops a number box (R14). Tests: Task 1, `test_a_filed_number_keeps_its_room_after_the_schema_drops_its_box`.
4. **Two groups overflowing at once.** E/F with more than six unsecured debts and more than seven notice parties numbers every page across both groups' copies. Tests: Task 6, `test_both_groups_overflowing_number_every_page_across_both`.
5. **Two debts on one property.** Both print Columns B and C blank (C6), and the Amounts Owed step shows the C-1 note under each. Tests: Task 2, `test_column_b_is_blank_when_two_debts_share_the_property`; Task 7, `shows the co-owned note when another debt is secured by the same property`.

## Rulings

These settle what the spec leaves open or the code contradicts, and name what each costs if wrong. `rulings` in a task means this section.

- **R1. The rows: `apps/intake/claim_rows.py`, pure.** It imports no model and reads relations by attribute, as `claims.py` does: `session.debts.confirmed()`, `session.executory_contracts.all()`, `session.codebtors.all()`, `session.assets.all()` through `ordered_assets`, and `getattr(session, "claim_answers", None)`. It returns row objects holding the model rows and the derived facts (line, who owes, Columns B and C, H citations). Formatting to text is `CLAIM_CELLS`' job in `fill_resolver.py` (Task 3), as `ASSET_CELLS` formats A/B rows.
  - Why: the spec puts `CLAIM_CELLS` in `fill_resolver.py` "as `ASSET_CELLS` does", and the money helper (`money_or_blank`) lives with the forms. Cost if wrong: none; one module could hold both.
- **R2. The six lists and their order** (§9.1, §9.3).
  - `secured`: confirmed debts with `is_secured` True, in `ordered_debts` order. D Part 1; lines "2.1", "2.2", ….
  - `unsecured`: confirmed debts with `is_secured` False, in `ordered_debts` order. E/F Part 2; lines "4.1", ….
  - `secured_notices` and `unsecured_notices`: for each debt of that list in order, its notice parties in stored order. D Part 2 and E/F Part 3. Each row carries its debt's line.
  - `contracts`: every contract, by pk (B37). G; lines "2.1", ….
  - `codebtors`: every codebtor, by pk, as one or more H rows (R6).
  - Lines are counted over these lists alone, so a draft never shifts a line. The same function gives every row its line and every citation (D Part 2, E/F Part 3, H), so they can't disagree.
  - The partition agrees with every bound rule (checked): `has_secured_debts`, `total_secured_debts` read confirmed `is_secured`; `has_nonpriority_debts`, `total_nonpriority_unsecured` confirmed not `is_secured`; `total_student_loans` confirmed, not secured, `debt_type == "student_loan"`. Cost if wrong: rows and totals disagree; Tasks 5, 6 and 8 pin each total against its rows.
- **R3. Who owes** (§9.3). A debt owes "At least one of the debtors and another" when a codebtor of the session links to it (R6's live links), else "Debtor 1 only". "Debtor 2 only" and "Debtor 1 and Debtor 2 only" never tick. The template has three shapes for the four ticks, and the generator binds each as it is:
  - One name with four named states (D `check 2`, `check 3`, `check 4`; E/F `check 6`–`check 11`): one binding `claims.<list>[].who`, choices `{"debtor_1": <its Debtor 1 only state>, "another": <its at-least-one state>}`, the states read from the template.
  - One name, four `/On` widgets (D `check 5`): two tagged bindings, `check 5@2:T51` on `who_debtor_1` and `check 5@2:T56` on `who_another`, each `{"true": "/On"}`.
  - Four names (D slot 5): `Debtor 1 only_5` on `who_debtor_1` and `At least one of the debtors and another_5` on `who_another`, each `{"true": "/On"}`.
  - Cost if wrong: none to a figure; a co-signed debt shows the wrong tick.
- **R4. What the gap table doesn't ask doesn't print.** Each of these mirrors `claim_step_gaps`' own condition:
  - Column B reads the row's `details["who"]` on a shape that asks who (`asks_who`: lines 1, 3, 4) and the debt's `collateral_who` on any other shape, never the other one, which may be left from an earlier link (§9.4, B25).
  - H line 2 prints the state and the spouse's name and address only when `community_lived` and `community_spouse_lived_with` are both "yes"; `check3` prints only when `community_lived` is "yes" (`_community_gaps`, `claims.py:384-408`).
  - An address ticked `outside_us` prints blank state and ZIP, whatever is stored (B49).
  - A codebtor's link counts only when it names a confirmed debt or a contract of this session; a dead link, a draft or another session's row is no link.
  - D has no offset box and E/F no lien, property or Column B box, so a stale offset on a secured debt or a stale lien on an unsecured one has nowhere to print. `home_payment_line`, `monthly_payment` and a lease's kind, vehicle and payment print on no schedule (G prints name, address and "what it is for", §9.3).
  - `community_debt` prints as stored: the gap table never asks it, and it is the filer's own tick (B33). `date_incurred` and a last 4 print as stored, blank when empty (B32).
  - Cost if wrong: a sworn box prints an answer the filer can't see. Review Focus 2.
- **R5. Columns B and C** (§9.4), for a secured row:
  - No live link (`link_is_live`): both blank.
  - Another confirmed secured debt of the session links to the same asset (C6): both blank on each.
  - A shape that asks who: `who == "only_you"` and `entire_value is not None` gives B = `entire_value`; otherwise both blank (`with_someone`, unanswered, or unknown).
  - Any other shape: `collateral_who == "only_you"` and `current_value is not None` gives B = `current_value`; otherwise both blank.
  - C = max(0, A − B) whenever B prints, so it prints "0.00" when the property covers the debt (§9.4: "both inputs exist, so it isn't an invented zero").
  - Cost if wrong: a sworn Column B or C on co-owned or shared property. No persona has C6; Andrés's Copperline is the `with_someone` case.
- **R6. H rows: two citations a box** (B40, measured). A codebtor's citations are the lines of its live links, by schedule: D (secured debts), E/F (unsecured debts) and G (contracts), each in line order. Each H row's box holds at most two, joined with ", ". A codebtor prints as many rows as its longest schedule needs, at least one, each with the same name and address: row k carries the k-th pair of each schedule, and a schedule's tick is on only where that row's box holds a line.
  - Why two: `fit` measured H's 42.5 pt box: any two lines up to "4.10, 4.11" fit (8.5 pt), "4.10, 4.11, 4.12" doesn't, and three one-digit lines fit only at 7 pt. Two always fits: D and E/F stop at line 99 (row 100 is refused, R8), and G reaches row 999, whose widest pairs ("2.100, 2.101", "2.998, 2.999") fit at 6.5 pt. Cost if wrong: a codebtor with three one-digit links takes two rows where one would do.
  - No pixel check (spec §13 asks for one on H's line boxes): a line box is no number box, so `fit` keeps its text inside the field's width, and only a number box's extra room can reach the clip. `fit` alone is the measure.
- **R7. The generator writes the four schemas whole.** `build_claims_schedules.py` owns `schedule_d.json`, `schedule_e_f.json`, `schedule_g.json` and `schedule_h.json`: their header bindings as today (`Debtor 1`, the district combo, line 1's `check1` or `check7`, E/F's three totals), their groups, page numbers and slots, written in `build_schedule_a_b.py`'s key order with its `dumps`. In `step2_verification.json` it owns only the rows whose producer it writes, `asked:claims.…` and `derived:schedule_h_…`. The rows already there for the header bindings (G 2, H 2, D 1, E/F 4) stay untouched. It removes its own rows and writes them again just after the last row of the same schema, so a re-run changes nothing.
  - A test, `test_the_claims_schedules_are_what_the_generator_writes`, builds in memory and compares with the committed files. `build_schedule_a_b.py` has no such test, and nothing else would stop a hand edit.
  - Cost if wrong: none.
- **R8. Groups, numbers and page numbers** (§9.1, §9.3, from the template survey).
  - `d_part_1`: capacity 5 (page 1 rows 1–2, page 2 rows 3–5), `extra_page` 2, `number` "2.{n}", `number_boxes` `{"3": "undefined_12", "4": "undefined_19@2:T37", "5": "undefined_19@2:T63"}`, `totals` `{"column": "claims.secured[].amount", "page_boxes": {"1": "undefined_9", "2": "undefined_23"}, "last_page_box": "undefined_24"}`.
  - `d_part_2`: capacity 6 (page 3), `extra_page` 3, no `number` (its entry box stays blank, B41).
  - `ef_part_2`: capacity 6 (page 3 rows 1–3, page 4 rows 4–6), `extra_page` 4, `number` "4.{n}", `number_boxes` `{"4": "undefined_4.4", "5": "undefined_4.5", "6": "undefined_4.6"}`.
  - `ef_part_3`: capacity 7 (page 5), `extra_page` 5, no `number`. Its page prints "5.1"–"5.7", so a copy repeats them, as a copied paper page would. No row cites a Part 3 line. Cost if wrong: a copy's preprinted numbers read as duplicates.
  - `g`: capacity 13 (page 1 rows 1–5, page 2 rows 6–13), `extra_page` 2, `number` "{n}", `number_boxes` rows 6–13 on `fill 2.6`–`fill 2.13`.
  - `h`: capacity 11 (page 1 rows 1–3, page 2 rows 4–11), `extra_page` 2, `number` "{n}", `number_boxes` rows 4–11 on `fill 3.4`–`fill 3.11`.
  - Page numbers, at the schema's top level: D as conftest's `_D_PAGE_NUMBERS`, E/F as `_EF_PAGE_NUMBERS` (pages 5 and 6 share the "of" box `fill_27.1.7`), G and H `[{"page": 1, "this": null, "of": "fill_27.0"}, {"page": 2, "this": "fill_27.1.0", "of": "fill_27.1.1"}]`.
  - D's `undefined_24` loses its `total_secured_claims` binding: a group declaring the box makes the binding E006 (3c1 R1). The rule's alias goes from `DERIVATIONS` and `RULE_FIXES`, since nothing else binds it (grep: no test names it). 106Sum line 2 keeps `total_secured_debts`, the same function.
  - Limits after this PR, as 3c1 R8 says: D and E/F row 100 ("2.100"), G row 1000, page 1000.

A row on a copy sits in a slot whose own line differs, so a line in the label would name the wrong row. The words are the table in Task 4's Interfaces.

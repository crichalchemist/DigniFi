# Forms step 4b, Your Information on Form 101 (11/26): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Form 101 prints on its 11/26 revision from a hand-adjudicated index and a tool-written schema, the 06/24 template retires with a plain 422 for a row filed on it, and the filer's own Form 101 answers (step 1's ten questions, step 5's hazard, step 7's rent and eviction with the Form 101A notice) are stored encrypted in `PetitionAnswers` and print in the boxes that ask them, with Form 121's ITIN boxes and 103B line 20 reading the same record.

**Architecture:**

- **The template and its index** (`data/forms/pdfs/form_b101.pdf`, `data/forms/field_index/form_b101.index.json`, `tools/build_form_101_index.py`): the court's file downloaded again, its URL, date and sha256 in the README; the index read off the PDF by a tool from a hand table keyed by page and rectangle (B55), typed Text / CheckBox / RadioButton / Signature, one tag per widget (the `District` twin and the 7 radio pairs included), and a template test that fails on any difference. No vision run.
- **The schema** (`tools/build_form_101.py` → `data/forms/schemas/form_101.json` and its rows in `audit/step2_verification.json`): every bound box is a table row keyed by the index label; every choice option is a single box `{"true": "/On"}` fed by a derivation that returns `"true"` or `""` (B56); the 7 real yes/no pairs are radios with the group's own states; one answer spans several boxes through the digit, Number/Street and court-split derivations; every asked box binds a `petition.` key, blank until its step asks it. The 06/24 PDF, index and schema go; the audit, unbound and verification files stay as the 06/24 record.
- **The record** (`apps/intake/models.PetitionAnswers`, migration 0044, `IntakeSessionSerializer.petition_answers`, `apps/intake/petition.py`): one `EncryptedTextField` JSON column, a closed `KEYS` list, store-then-flag validation (B47), `answered_on` server-stamped; `petition_step_gaps(session) -> list[Gap]` is the first gap function to produce a `detail`, and joins `completion_gaps` by step the moment step 1 asks (Task 7, 4b-ii), not before. Each `detail` names the forms whose box prints blank (`Gap.forms`), so the dashboard can repeat it on those cards (§5.7: "the PR that adds the first one builds it"; Task 9b).
- **The steps** (`components/wizard/steps/petition/`): step 1's ten questions in Form 101's words after the county block, the hazard block at the end of Assets, the rent and eviction block on Contracts & Leases with the Form 101A and 101B notice (`[Q1 both]`, the early half); each step's body carries only its own keys (the `CODEBTOR_ANSWER_KEYS` rule); the public-record notice takes the clerk's number from the county's division.
- **The split.** 4b is XL, and this plan is written in two halves that each merge green on their own: **4b-i** (Tasks 1–6: the record without its step, the template, the index, the derivations, the schema tool, the retirement, the suite's 06/24 references, the filed-row 422) changes what Form 101 prints for no filer and asks no question; **4b-ii** (Tasks 7–12, 9b among them: the gaps joined, the three step blocks, the dashboard's per-card line, Form 121 and 103B, personas and E2E, the docs). Section "Rulings", 4b-R1.

**Tech Stack:** Django 5.0 + DRF, pytest-django (sqlite; `test_session_lock.py` and the migration tests under Postgres), pypdf + PyMuPDF (`fitz` 1.27.2.3 in `backend/.venv`), React 19 + Vite + TypeScript, vitest + MSW + vitest-axe, Playwright. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-18-forms-step4-design.md` (cited `§n`; row 4b is §19 line 806; builder's calls `Bn`), read whole on 2026-11-19, with `SF101N` (`.claude/handoff/2026-11-18-step4/design/survey-f101-1126.md`, Appendix A the widget table) and `SF101` (`survey-f101.md`, the 06/24 audit). Every `path:line` below was read in this worktree at 4027940 on 2026-11-19; a task that lands earlier moves the ones below it. The patterns 4b reuses are 4a's (`docs/superpowers/plans/2026-11-18-forms-step4a.md`: `Gap`, `completion_gaps`, the namespaces in `answer_records.py`, `YesNoThenDetails`, `PublicRecordNotice`, the gaps endpoint).

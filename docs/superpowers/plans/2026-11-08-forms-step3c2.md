# Forms step 3c2, row foundations: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Encrypt the debt, contract and codebtor columns, read debts in the forms' creditor order, and give Contracts and Codebtors the wizard's list pattern (held rows, autosave, ids paired by position), with no new question for the filer.

**Architecture:**

- **Encryption.** Each listed column moves to an encrypted twin in three migrations, as `0032`–`0034` did for assets: add, copy in batches, swap.
- **Debt order.** A dropped `Meta.ordering` gives way to `ordered_debts`, a pure sort in the new `apps/intake/claims.py`.
- **List saves.** The list PUT takes the session lock before it checks a row, and replies in the order it was sent.
- **The wizard.** It holds both lists as keyed rows, builds a body for steps 7 and 8, and pairs each reply's ids exactly as it does for assets.

**Tech Stack:** Django 5.0, DRF, `encrypted-model-fields`, pytest-django with sqlite (and Postgres for the lock test). React 19, TypeScript, vitest with MSW. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-06-forms-step3c-design.md` §6 (cited `§`), with §1, §2's standing rules, §3.1 (S18, S19), §4 and B3, B5, B9, B11 and B37. Where this plan and the spec disagree, the spec wins, except at "Rulings".

## Review Focus

These are five conditions the spec implies but §6.5 doesn't name, ordered by how likely they are to bite a filer. Each has its test in the owning task.

1. **A monthly payment typed as $0.** It is sent as 0 and comes back "0.00", never emptied by the cleared-payment fix (Task 5, `saves a monthly payment typed as $0 as 0, not as empty`).
2. **An edit while a list save is on its way.** The row settles on the id the server holds, with no save loop (Task 4, `keeps the id the server holds when the filer edits while a save is on its way, without a save loop`).
3. **A row removed while its save is on its way.** It stays removed, and the other new row keeps its id (Task 4, `drops a row the filer removed while its save was on its way`).
4. **A creditor name typed with a leading space.** It sorts by its first letter, not ahead of every name (Task 2, `test_a_name_typed_with_a_leading_space_sorts_by_its_first_letter`).
5. **A corrected creditor name of exactly 255 characters.** It is kept, while 256 characters is refused (Task 1, `test_a_corrected_creditor_name_of_exactly_255_letters_is_kept`).

## Rulings

These settle gaps the spec leaves open.

- **R1. Encryption lands before order.**
  - Task 1's migrations are `0036_claims_encrypt_add`, `0037_claims_encrypt_copy` and `0038_claims_encrypt_swap`.
  - Task 2's is `0039_debtinfo_no_ordering`.
  - So Task 2's order tests run on ciphertext columns, and a database sort on `creditor_name` fails them, as §6.5's "doesn't depend on ciphertext" requires.
  - Until Task 2, `Meta.ordering`'s `-amount_owed` sorts ciphertext, as it already does today.
- **R2. `monthly_payment` takes the three steps too (§6.1).** Altering a numeric column in place to an encrypted one would leave the old figures as plaintext digits in the table.
- **R3. Each twin is the field's final definition, so the swap's rename leaves the migration state equal to the models.**
  - The three required names (`creditor_name`, `counterparty_name`, Codebtor `name`) are added with a one-off `default=""` and `preserve_default=False`.
  - A blank field (`blank=True`) adds as it ends.
  - `relationship` keeps its choices and `default="other"`.
  - `creditor_name`'s new help_text (Task 1) goes on its twin.
  - Before the swap, every NOT NULL plaintext text column gains `default=""`, as `0032` did, so undoing the swap can put them back on a table with rows: `creditor_name`, `notes`, `collateral_description`, `counterparty_name`, the contract's `description`, and the codebtor's `name`, `street_address`, `city`, `state` and `zip_code`.
  - `makemigrations --check` proves the state matches the models. `deconstruct` drops `max_length`, so the check can't see a width, but it sees blank, default, choices and help_text.
- **R4. `date_incurred` becomes encrypted text (B11, confirmed).**
  - The national instructions for Schedules D and E/F (page 6) say: "When a debt was incurred on multiple dates, fill in the range of dates. For example, if the debt is from a credit card, fill in the month and year of the first and last transaction."
  - The forward copy writes `isoformat()`.
  - Undoing the copy keeps a value `datetime.date.fromisoformat` reads, and turns any other value into null, losing its text (§6.1).
  - It has no reader or writer until 3c3.
- **R5. Serializer declarations repeat today's auto-mapped kwargs exactly, plus `min_value=0` on `monthly_payment` (§6.1).**
  - An `EncryptedDecimalField` would otherwise map to a 20-character string field.
  - The widths stay where the old columns had them, so undoing the migration never meets a wider value.
- **R6. A scanned bill's correction refuses a blank or null creditor name too.** It uses `serializers.CharField(max_length=255)`, whose defaults refuse blank and null.
  - Today a blank saves a nameless draft. The Amounts Owed step's body then leaves that draft out, and the save deletes it.
  - Today a null is a 500, since the column is NOT NULL.
  - `validateDocument` has no caller in the frontend, so no screen sends either.
  - Cost if wrong: a 400 where a blank used to save.
- **R7. The sort key is the name stripped of surrounding spaces, decomposed (NFKD) with combining marks removed, and casefolded, then the pk.** `casefold()` alone sorts "É" after "z". §6.5 asks that "case and accents sort as letters", and the forms ask for "alphabetical order according to the creditor's name", which a leading space would defeat.
- **R8. The session serializer re-serializes `ordered_debts(instance.debts.all())`, before its `sent_rows` override.**
  - That way one function decides the order, and a PATCH reply keeps sent order.
  - The rows are prefetched (`views.py:146`), so this costs no query.
  - This corrects §6.2's "as it does assets": assets are sorted by id in `to_representation`, not by `ordered_assets`.
- **R9. `DischargeabilityService.evaluate` reads `ordered_debts(...)` (not in §6.2).**
  - Its results are an API list (`DebtExplanationsPanel`).
  - Once `Meta.ordering` goes, it would otherwise come in the database's unspecified order.
  - `dischargeability_classifier.py` has no caller and is left as it is.
- **R10. Corrections to §6.5's pin list.**
  - `test_session_nested_save.py:356` moves too: it compares against `Meta.ordering`.
  - `documents/tests/test_draft_debt.py`'s `debts[0]` indexes the list `create_from_credit_report` returns, and `test_data_migrations.py:126` reads the historical model at `0011`, where the name is plaintext. Neither moves.
  - So "the three plaintext lookups" are two: `test_dischargeability_service.py:50` and `:96`.
  - Two pins §6.5 doesn't name move with Task 1, both in `intake/tests/test_models.py`:

NULLABLE = {"monthly_payment", "date_incurred"}


def _forward(name, value):
    if name == "date_incurred" and value is not None:
        return value.isoformat()
    return value


def _back(name, value):
    if name == "date_incurred":
        try:
            return datetime.date.fromisoformat(value) if value else None

import unicodedata


def _letters(name):
    """A creditor's name as it sorts: its letters, without accents, ignoring case."""
    decomposed = unicodedata.normalize("NFKD", name.strip())
    return "".join(c for c in decomposed if not unicodedata.combining(c)).casefold()

    """The rows alphabetical by creditor name, ignoring case and accents, then by id.

    """
    return sorted(rows, key=lambda row: (_letters(row.creditor_name), row.pk))

```python
def _save_list(session, model, row_serializer, rows):
    """Save the whole list the Contracts or Codebtors step shows (DIG-147).

    The session is locked first, so a check that reads the stored rows sees the last save's.
    Every row is checked before anything is written, so one bad row saves nothing. Then a row
    carrying one of this session's ids updates in place, any other row is created, and a
    stored row the list left out is deleted (see _save_rows_by_id). Returns the saved rows in
    the order sent, each with its id, so the wizard pairs them by position (3c spec §6.3).
    """
    with transaction.atomic():
        lock_session(session.pk)
        serializer = row_serializer(data=rows, many=True)
        serializer.is_valid(raise_exception=True)
        saved = _save_rows_by_id(session, model, serializer.validated_data)
        session.reopen()
    return Response(row_serializer(saved, many=True).data)
```

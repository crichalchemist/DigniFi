# Forms step 3h2, the 122A-2 page: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An above-median filer answers every question Form 122A-2 asks on one page after `/exemptions`, the spouse's own vehicles and loans among them, and line 43 with a guided writing aid; the calculator reads those answers, so the in-app result is the form's arithmetic in the owner's words; 122A-2 and 122A-1 refuse with the page's first gap, then with a fixed "can't print yet" sentence until 3h3 prints the form.

**Architecture:**

- **Calculator** (`apps/eligibility/means_lines.py`, pure): vehicles and debts are named by string refs (`asset-<pk>`, `debt-<pk>`, `spouse-<id>`) so a Schedule A/B row and a spouse row can't be mistaken; it adds the spouse's two answers, H57's slot rule, the line 15 and line 30 caps (a figure above a cap is `MISSING`), and four public helpers the page and the browser share: `slot_candidates`, `debt_lines`, `plan_product`, `rebuttal_figure` (plus `line_30_cap` and `sixty_month_total`). Three case files, run by both sides, pin the browser's copies.
- **Records** (`apps/intake/models.py`): `MeansTestAnswers` (one encrypted JSON column, one-to-one with the session) and `SecuredDebtAnswers` (one-to-one with a `DebtInfo`, cascade, every column encrypted). Neither is intake data: nothing on the page reopens a completed intake.
- **Reader** (`apps/eligibility/means_inputs.py`): `read_inputs` reads the stored answers through `normalized_answers` (`apps/intake/means_test.py`, pure), which reads a reference to a row that has gone as unanswered.
- **Endpoint**: `GET`/`PUT /api/intake/sessions/{id}/means-test/` (`IntakeSessionViewSet.means_test`). The PUT validates shapes and fits outside the lock (`MeansTestSerializer`, `apps/forms/services/means_fit.py`), then locks, checks every reference against stored rows, writes and stamps `debts_answered_on`; the reply is the GET body (`apps/intake/means_page.py`), worked out again after the write.
- **Gate**: `means_test_gaps` (`apps/intake/means_test.py`) lists every gap in page order; 122A-2's `requires()` refuses a missing table, then the first gap (`page="/means-test"`), then `FORM_122A2_CANT_PRINT_YET`; 122A-1 follows it, as in 3h1. The packet reply gains `means_debts_answered`.
- **Frontend**: `/means-test` (`MeansTestPage.tsx` and `pages/meansTest/`), with browser copies of the gaps, the grouping, the product, the rebuttal figure and the draft; the dashboard, the card and the sidebar show the result in O4's words with the link to line 43 under a presumption.

**Tech Stack:** Django 5.0, DRF, `encrypted-model-fields` (Fernet), pypdf/PyMuPDF form engine (measurement only), pytest-django (sqlite; Postgres for the `postgres` marker), React 19 + Vite + vitest + MSW, Playwright. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-13-forms-step3h-design.md` (the 3h2 amendment approved by the owner on 2026-11-15), §8 (cited `§8.x`, §8.12 included), with §6's 3h2 rule, §11's copy rules, §15's calls (cited `Hn`) and Appendix A. Where this plan and the spec disagree, the spec wins, except at "Rulings". ## Global Constraints

- **The filer's own answers, nothing more.** No answer on the page is pre-selected or pre-filled: no radio, vehicle, Vehicle 1 or 2, "60 or more", circumstance or line 43 answer on load, and no amount copied from a Schedule I or J figure (O1, H18, U:571). A figure shown beside a line is information read from what the filer entered, labelled with where it came from, never compared with the answer and never suggested.
- **Not intake data.** Nothing the page saves reopens a completed intake: no `reopen()`, and none of its answers is a session-PATCH key (P1, H7). Complete is unchanged.
- **The PUT's order (§8.4).** `get_object()` (another user's session is a 404); the shape checks that read nothing stored (`MeansTestSerializer.is_valid`); then `lock_session(session.pk)` inside `transaction.atomic()`; then, under the lock, every check that reads a stored row; then the write. Nothing reads a stored row before the lock.
- **No catch-alls (H9).** No `except Exception`, no fallback to 0, no `or Decimal("0")` in new code. A missing answer makes its line `MISSING`; a table key the set should hold and doesn't raises `MeansTableKeyMissing`.
- **Rounding (H3, P5).** Every money line is a `Decimal` quantized to `Decimal("0.01")` with `ROUND_HALF_EVEN`; a ÷ 60 row rounds per row; later lines add the rounded figures. The browser copies of line 36's product and the rebuttal figure use integer cents and the same half-even rule.
- **Line 43 never moves a box or the result** (§1): it is no input of `compare()` or of `MeansTest.outcome`, and nothing on the page derives a line 43 answer.

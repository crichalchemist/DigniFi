# Forms step 3g1, exemptions: ask and store: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A page after the filing-fee page asks Schedule C's line 1, the filer's claims (an item from their Schedule A/B, a law from one dated list, an amount) and lines 3 and 3-1, stores the answers encrypted, and Schedule C is refused, with a link to the page, until it is answered; the old, unread exemption figures go.

**Architecture:**

- **The law list is dated data.** `ExemptionCatalog(DatedTable)` and its `ExemptionLaw` rows live in `apps/districts`, loaded by a data migration as `PovertyGuideline` is, and are looked up through `in_force` on the fill date (B2). The page shows each law's citation, a summary from `copy.ts` and the law's own limit sentence from the catalog.
- **Two records, not intake data.** `ExemptionAnswers` (line 1, line 3, line 3-1, "not claiming") and `ExemptionClaim` rows (an item by FK, a law or a typed law, an amount) are encrypted, saved under the session lock through one endpoint, `GET`/`PUT /api/intake/sessions/{id}/exemptions/`, and never reopen a completed intake (the `FilingFee` pattern).
- **What Schedule C copies from Schedule A/B is worked out from A/B itself.** A forms-side module gives each A/B row its name (B12), the line label A/B prints for it (B13, read from A/B's schema and index), the value A/B prints in its portion box (B16) and whether the name fits Schedule C's description box (B6, measured with the forms' own `text_fit`).
- **One gap list, two copies.** `exemption_gaps` (pure, in `apps/intake/exemptions.py`) names every gap in page order; Schedule C's `requires()` raises the first with `page="/exemptions"`; the page's `exemptionGaps.ts` copies it, its sentences pinned to the server's.
- 3g2 prints. Nothing in this plan binds a Schedule C box.

**Tech Stack:** Django 5.0, DRF, `encrypted-model-fields`, pypdf/PyMuPDF (measuring only), pytest-django with sqlite; React 19 + Vite + vitest + MSW; Playwright for the journeys. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-12-forms-step3g-design.md` §5 (cited `§5.x`), with §2, §3, §7, §8's 3g1 items, §9's DIG-286 and §11's calls B1–B8 and B11–B17. ## Global Constraints

- **No code chooses for the filer.** No law, amount, line 1, line 3 or 3-1 answer is pre-selected, suggested, filtered, sorted per item or filled in. Every claim's law control lists the same laws in the same order whatever its item. A "100% of fair market value" claim is never given a dollar figure (§1 anti-goals).
- **Totals are neutral.** A per-law total over its limit renders exactly like one under it: same markup and class, no colour, no `role="alert"`, no blocked Continue (C-LIMITS b).
- **Not intake data.** Saving the exemptions answers never calls `IntakeSession.reopen()`; a completed intake stays completed (§5.2).
- **Encrypted.** Every column of `ExemptionAnswers` and `ExemptionClaim` but the FKs and timestamps is encrypted; the server orders rows in Python (U:86). The catalog is national public data and is not encrypted.
- **Saves lock the session.** The PUT calls `get_object()` first, then `lock_session(session.pk)` inside `transaction.atomic()` before reading any of the session's data (CLAUDE.md "Saves lock the session").
- **Words.**
  - The form's own words go in `frontend/src/constants/formText.ts` (unscored, unmarked). DigniFi's sentences go in `frontend/src/constants/copy.ts`, each at grade 9 or below by `reading-level.test.ts`.
  - Every DigniFi sentence about the law (the introduction, the two line 1 notes, the law summaries, "This law names no dollar limit.", the two total templates) has `// DRAFT: counsel C-8` on the line directly above its `export const`. The catalog's limit sentences carry `# DRAFT: counsel C-8` in their migration.
  - No new sentence says "should", "recommend", "you must", "advise", "qualify", "protect", "covered", "you keep", "best set" or "eligible". Law summaries and limit sentences contain no "you" and no `$` in a summary.
  - A gap sentence the server and the page both hold is one string literal in `copy.ts` (`export const NAME = '…';`, or double quotes when it holds `'`), so `test_exemption_copy.py` can read it.
- **Logs and errors.** No logger call, exception message or `__str__` carries an answer, a law, a typed law, an amount or a description.
